## 1. 5 Core Mental Models Every Expert Shares

1. **Decomposition** — Break large problems into small, testable functions.
2. **Abstraction** — Hide implementation details behind clear interfaces.
3. **Debugging as Scientific Method** — Form hypothesis, test, isolate, fix.
4. **Data Structures Dictate Algorithms** — Choose the right structure first.
5. **Readability is a Feature** — Code is read more often than written.

---

## 2. 3 Places Experts Fundamentally Disagree

### Disagreement 1: Imperative vs Functional as First Style
- Imperative is closer to hardware and easier for beginners; Functional reduces bugs and scales better for concurrent systems.

### Disagreement 2: How Early to Teach OOP
- Early OOP builds design thinking; Late OOP lets students master pure logic and control flow first.

### Disagreement 3: Role of AI Coding Assistants in Learning
- Useful accelerator if students still understand the generated code; Harmful if it replaces thinking.

## 3. 10 Questions that Distinguish Deep Understanding

1. Why is mutation often considered more dangerous than pure functions?
2. When would you choose a list over a dictionary (or vice versa) and why?
3. What does 'referential transparency' mean and why does it matter?
4. How do you systematically isolate a bug that only appears intermittently?
5. Why is premature optimization considered a root of evil?
6. Explain the difference between pass-by-value and pass-by-reference with a concrete example.
7. How does choosing the wrong data structure turn an O(n) algorithm into O(n²)?
8. What is the difference between a syntax error, runtime error, and logic error?
9. Why should functions ideally have a single responsibility?
10. How would you test a function that depends on external state (file, sensor, network)?
